# Ozon Parser — тестовое задание

Парсер данных о товарах Ozon: авторизация в личном кабинете продавца
(data.ozon.ru) и сбор карточек товаров по списку SKU.

## Структура проекта

ozon_parser/
   .env # настройки (не в git)
   requirements.txt
   gmail_auth.py # работа с Gmail API: OAuth + поиск кода в письме
   get_cookies.py # получение cookies авторизованной сессии
   parse_ozon.py # парсинг карточек товаров по SKU (в разработке)
   cookies.json # сохранённые cookies (не в git!)
   credentials.json # OAuth client Google (не в git!)
   token.json # токен доступа Gmail (не в git!)
   output/
      products.csv

## Установка

```bash
pip install -r requirements.txt
playwright install chromium
```

## Настройка Gmail API

1. Создать проект в [Google Cloud Console](https://console.cloud.google.com/).
2. Включить Gmail API (APIs & Services → Library).
3. Настроить OAuth consent screen (тип External, добавить себя в Test users).
4. Создать OAuth Client ID (тип Desktop app), скачать как `credentials.json`.

При первом запуске откроется браузер для подтверждения доступа;
токен сохранится в `token.json` и будет переиспользоваться дальше.

## Как устроен вход (get_cookies.py)

### Важная находка: почему вход реализован именно так

Изначально предполагался классический сценарий: Playwright кликами
проходит форму логина, код подтверждения читается из письма через
Gmail API. В процессе разработки выяснилось два независимых
ограничения, которые сделали такой путь непрактичным:

1. **Антибот-защита Ozon.** В сетевых запросах при логине виден
   отдельный домен антифрод-сервиса (`rsa.stg.ozonru.me`). На практике
   любой запуск Playwright/Chromium (в том числе со
   `playwright-stealth` и с флагом `channel="chrome"`) блокировался
   экраном "Похоже, нет соединения" ещё до формы логина — то есть
   антибот-система отличает автоматизированный браузер от обычного.

2. **Chrome App-Bound Encryption.** Начиная с Chrome 127+ файл cookies
   на диске шифруется так, что сторонние библиотеки
   (`browser_cookie3` и аналогичные) больше не могут расшифровать
   его напрямую (`RuntimeError: Failed to decrypt the cipher text
with DPAPI`) — это подтверждённое системное ограничение самого
   Chrome, а не проблема кода.

3. **Канал доставки OTP-кода.** При входе через `data.ozon.ru` по
   email в качестве идентификатора, код подтверждения в
   протестированном аккаунте приходил push-уведомлением в приложение
   Ozon Job на телефон, а не на почту (подтверждено сравнением
   сетевых запросов и содержимого реально полученных писем).
   Модуль чтения кода из Gmail (`gmail_auth.py`) реализован и
   протестирован отдельно и подтверждённо работает — читает свежие
   письма от `mailer@sender.ozon.ru`, корректно отсекает старые
   письма по времени получения, извлекает код по regex.

### Итоговое решение

`get_cookies.py` не управляет браузером напрямую, а подключается
к уже запущенному пользователем Chrome через Chrome DevTools
Protocol (`playwright.chromium.connect_over_cdp`) и забирает
cookies текущей сессии через официальный API браузера — это снимает
оба ограничения выше: логин выполняет реальный человек в обычном
браузере (антибот пропускает), а cookies отдаёт сам Chrome, без
обращения к зашифрованному файлу на диске.

Поддержка чтения OTP из Gmail (`OTP_SOURCE=gmail` в `.env`)
оставлена в проекте рабочей и протестированной — для аккаунтов/
сценариев, где Ozon действительно присылает код на почту, вход
может быть доведён до полностью автоматического при доработке
кликов формы логина в `get_cookies.py` (сейчас закомментированный
черновик такого сценария также присутствует в истории разработки).

### Порядок запуска

1. Полностью закрыть все процессы Chrome.
2. Запустить Chrome с отдельным временным профилем и портом отладки:

```powershell
   & "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="C:\ozon_chrome_profile"
```

3. В открывшемся окне зайти на `https://data.ozon.ru/` и залогиниться
   (ввести код подтверждения — из SMS/push на телефон).
4. Заполнить env и запустить:

```bash
   python get_cookies.py
```

5. Cookies авторизованной сессии сохранятся в `cookies.json`.
